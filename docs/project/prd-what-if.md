## 0. 핵심 제약 (먼저 못 박기)

- **No DB.** 모든 사용자 데이터는 브라우저 로컬(IndexedDB)에만 저장. 서버는 OpenRouter 호출 프록시 역할만.
- **프라이버시가 기능이다.** 원문 카톡은 서버에 절대 저장 안 함. LLM 호출 시 **필요한 청크만 일시 전송**. UI에 "대화는 당신 브라우저에만 저장됩니다"를 명시 → 데모 셀링포인트이자 윤리적 기본값.
- **무료 스택.** LLM은 OpenRouter `openrouter/free` 라우터. 키 노출 막으려고 얇은 백엔드 프록시 1개만 둔다.
- **거대 입력 대응.** 수개월치 카톡 = 수만 줄. 통컨텍스트 투입 불가 → 로컬 통계 선분석 + 구간 분할 map-reduce.

## 1. 데모 시나리오 (the money shot)

발표는 이 한 흐름으로 끝낸다:

1. 전 여친 카톡 `.txt` 업로드 (3초)
2. 자동 파싱 → **타임라인 그래프**에 대화 밀도/답장 지연이 그려지고, 위험 구간에 **빨간 마커**가 찍힘
3. "헤어진 이유" 카드가 뜸 (근거 인용 포함)
4. 빨간 마커 클릭 → **"여기서 이렇게 말했더라면"** 버튼
5. AI가 **대체 카톡 흐름**을 카톡 버블로 생성 → 관계 결말이 달라짐
6. 객석 반응 → 끝

> 발표 오프닝 멘트: "여러분, '그때 내가 그 말만 안 했어도'라고 후회해본 적 있죠? 저희는 그 평행우주를 실제 카톡으로 보여드립니다."

## 2. 기능 명세

### P0 (데모 필수)

1. **카톡 txt 업로드 & 파싱** — 기기/언어별 포맷 자동 감지(§4)
2. **로컬 통계 분석 (LLM 0회)** — 답장 지연 시간, 대화 밀도 추이, 더블텍스팅, 대화 주도권, 밀도 급락 구간 탐지(§5)
3. **LLM 분석 파이프라인** — 구간별 분석 → 전체 종합 (map-reduce, §6)
4. **결과 3종** — ① 헤어진 이유(근거 인용) ② 위험했던 구간 ③ 내 실수 구간(+더 나은 버전)
5. **반사실 시뮬레이션** — 특정 순간 선택 → 대체 대사 + 갈라진 타임라인 생성(§7)
6. **IndexedDB 저장 & 복원** — 재방문 시 이전 분석 그대로

### P1 (시간 남으면)

- [x] 타임라인 시각화(밀도/답장지연 라인 + 위험 마커 클릭) — P0에서 구현됨
- [x] 분석 히스토리(여러 대화방) — IndexedDB
- [ ] 공유용 결과 카드(이미지 다운로드)
- [ ] "안전 선택 vs 미친 선택" 분기형 시뮬(앞선 멀티버스 카톡 컨셉 재활용)

### P1.5 — 발표 임팩트 (UX polish, §9.1)

P0 기능은 충분하나 **객석 후킹**을 위해 우선순위대로:

1. **관계 온도계** — 분석된 세션 `tension_score` 평균 또는 위험 top-N 기반 0~100 게이지 + 한 줄 요약
2. **타임라인 밀도 급락 밴드** — `stats.density` 급락 구간을 차트 배경에 빨간 밴드로 표시(마커와 시각적 정렬)
3. **반사실 split view** — 좌: 원본 한 줄 / 우: 평행우주 타임라인 + `outcome_delta` 배너
4. **분석 reveal** — MAP 진행 중·완료 시 stagger 애니 + "가장 아팠던 한 줄" 하이라이트 카드(`risky_moments` top1)
5. **랜딩·카피** — hero 서브카피 + **Three.js 3D 배경**(평행우주/분기 메타포). **UI 이모지 사용 금지** — 아이콘은 CSS/SVG/3D로 대체.

> 드라마틱 ≠ 비난. §7 톤 가이드와 §5B.4 그룹 톤 가이드는 그대로.

## 4. 파싱 명세 ⭐ (여기가 1번 함정)

> ✅ **실제 파일 2종으로 검증 완료** — ① 맥OS CSV(`공돌이들`, 4,414개) ② 안드로이드 영문 txt(같은 방, 38만 줄·5.7년치, 매치율 98%). 아래는 추측이 아니라 실측 반영본.
>
> ✅ **이 레포에서 재검증 완료(2026-06-27):** CSV BOM 존재, txt의 시각↔AM/PM 사이 문자 = U+202F, CSV 레코드 4,414 ≠ 줄 수 4,484, 그룹 참가자 5명(김건우·김주형·유기훈·정래현·한채린), 1:1 파일 참가자 [정래현, 서연이].

### 4.1 카톡 익스포트는 4종 포맷 — **맥OS는 CSV다**

실행 환경에 따라 형식이 완전히 다름. **맥OS는 `.txt`가 아니라 CSV로 빠진다**(원래 PRD에서 빠졌던 케이스, 그리고 가장 흔함). 4종 모두 처리.

**(D) 맥OS (CSV) — 가장 흔하고 가장 쉬움. 이게 메인 케이스:**

```text
Date,User,Message
2026-03-26 10:23:30,"정래현","님들 에반게리온 봄?"
2026-03-26 10:23:33,"정래현","개꿀잼임"
```

- 헤더 `Date,User,Message`, **UTF-8 with BOM** → 앞 `\uFEFF` 반드시 제거
- Date: **`YYYY-MM-DD HH:MM:SS`, 24시간제, 초 포함, 오전/오후 없음** (모바일과 정반대 — AM/PM 변환 불필요)
- User/Message는 큰따옴표(RFC-4180) → **콤마·줄바꿈 포함 메시지를 CSV 파서가 알아서 처리. 정규식 불필요.**

**(A) Android txt / (B) iOS txt / (C) PC txt** — §4.3 정규식 경로(직접 파싱).

**감지:** BOM 제거 후 1번째 줄이 `Date,User,Message` → CSV 경로. 아니면 앞 N줄 샘플링해 txt 포맷 분기.

### 4.2 CSV 경로 (맥OS — 메인 케이스, **정규식 쓰지 마라**)

프론트에서 **papaparse**로:

```js
import Papa from 'papaparse';
const text = (await file.text()).replace(/^\uFEFF/, '');         // BOM 제거
const { data } = Papa.parse(text, { header: true, skipEmptyLines: true });
// data: [{ Date, User, Message }, ...]
const ts = new Date("2026-03-26 10:23:30".replace(' ', 'T')).getTime(); // AM/PM 변환 없음
```

- papaparse가 따옴표·콤마·**대부분의 멀티라인**을 처리.
- ⚠️ **방어 1:** 카톡 CSV 멀티라인 이스케이프가 항상 완벽하진 않음 — 실측에서 `Date`가 빈 행이 6개 새어나옴(줄바꿈 누출). **`Date`가 비거나 파싱 실패한 행은 직전 메시지에 이어붙이거나 drop.**
- ⚠️ **방어 2:** `wc -l`(4,484) ≠ 실제 레코드(4,414). **줄 수로 메시지 수 세지 말 것** — CSV 파서 기준으로.

### 4.3 txt 경로 (Android/iOS/PC — 맥 아닐 때만)

> ✅ **실측: 안드로이드 영문 export** (`KakaoTalkChats.txt`). **안드로이드는 폰 언어 설정에 따라 포맷이 갈린다** — 한글폰=한글, 영문폰=영문. 둘 다 처리.

**전처리 — 이거 안 하면 정규식이 통째로 0매치 난다:**

```js
let text = raw.replace(/^\uFEFF/, '')                 // ① BOM 제거
              .replace(/\r\n?/g, '\n')                // ② CRLF/CR → LF (안 하면 $ 앵커 깨짐)
              .replace(/[\u202f\u00a0\u2009]/g, ' ');  // ③ ⚠️ 시각↔AM/PM 사이 U+202F → 일반 공백
```

> ⚠️ **최대 지뢰:** 안드로이드 영문 export는 시각과 `AM/PM` 사이가 일반 스페이스가 아니라 **U+202F(narrow no-break space)**. 정규화 안 하면 **매치율 0%**. (실측에서 이거 하나로 전부 안 잡혔다.)

**메시지 정규식 (로케일별):**

```js
const M = 'January|February|March|April|May|June|July|August|September|October|November|December';
// Android(영문): "October 2, 2020 at 3:02 AM, 한채린 : 메시지"  ← 실측 파일
const ANDROID_EN = new RegExp(`^(${M}) (\\d{1,2}), (\\d{4}) at (\\d{1,2}):(\\d{2}) (AM|PM), (.+?) : (.*)$`);
// Android(한글): "2024년 1월 1일 오후 2:30, 홍길동 : 메시지"
const ANDROID_KO = /^(\d{4})년 (\d{1,2})월 (\d{1,2})일 (오전|오후) (\d{1,2}):(\d{2}), (.+?) : (.*)$/;
// iOS(한글): "2024. 1. 1. 오후 2:30, 홍길동 : 메시지"  (iOS 영문은 ANDROID_EN과 유사 형태)
const IOS_KO = /^(\d{4})\. (\d{1,2})\. (\d{1,2})\. (오전|오후) (\d{1,2}):(\d{2}), (.+?) : (.*)$/;
// PC(한글): "[홍길동] [오후 2:30] 메시지" + 날짜 구분선
const PC_MSG  = /^\[(.+?)\] \[(오전|오후) (\d{1,2}):(\d{2})\] (.*)$/;
const PC_DATE = /^-{5,}\s*(\d{4})년 (\d{1,2})월 (\d{1,2})일.*-{5,}$/;
```

**라인 분류 (영문 안드 기준, 실측):**

- **헤더 2줄:** `KakaoTalk Chats <방이름> (<인원>)` + `Date Saved : ...` → 스킵. (1:1은 `KakaoTalk Chats with <상대>` 형태 — 실측 `(1).txt`.)
- **독립 날짜구분선:** `October 2, 2020 at 3:02 AM` (이름·콜론 없음) → 날짜 컨텍스트만, 메시지 아님
- **삭제 메시지:** `The message has been deleted.` (타임스탬프 없는 독립 줄, 전체 545개) → `isSystem`
- **입퇴장 시스템:** `<날짜>, 한채린 invited 정래현, 김주형 and 김건우.` (콜론 ` : ` 없음) → `isSystem`. 메시지 정규식이 `, (.+?) : ` 로 첫 콜론까지를 이름으로 잡으니 **콜론 없는 줄은 자동으로 메시지에서 제외**됨
- **멀티라인:** 위 어디에도 안 맞는 비어있지 않은 줄 → 직전 메시지 text에 `\n`으로 이어붙임 (실측 ~1.6%)

**타임스탬프:** 영문 `at H:MM AM/PM` → 24시간 변환(12 PM=12:00, 12 AM=00:00). 한글 오전/오후도 동일.

참고 구현: `uoneway/kakaotalk_msg_preprocessor`(기기/언어 자동 감지). 바퀴 재발명 금지.

### 4.4 시스템/미디어 메시지 플래그

실측: 미디어·삭제·입퇴장은 본문/줄에 리터럴 텍스트로 들어옴. 로케일별로 토큰이 다르니 둘 다 매칭. 다음이면 `isSystem=true`(분석 텍스트 제외, 통계엔 일부 활용):

- **미디어(메시지 본문):** 한글 `사진`·`이모티콘`·`동영상`·`음성메시지` / 영문 `Photo`(실측 6,500)·`N photos`(425)·`Video`(271)·`Emoticon(s)`·`Voice Note`
- **삭제:** 한글 `삭제된 메시지입니다` / 영문 `The message has been deleted.`(독립 줄, 실측 545)
- **입퇴장:** 한글 `님이 들어왔습니다`·`님이 나갔습니다`·`님을 내보냈습니다` / 영문 `... invited ...`·`... left.`·`... removed ...`
- 순수 URL만 있는 메시지 → 별도 플래그(콘텐츠 공유 신호)

### 4.5 출력 + 참가자 수 (1:1 vs 그룹)

```ts
type Msg = { ts: number; sender: string; text: string; isSystem: boolean; isUrl?: boolean };
type ParseResult = { format: 'csv'|'android'|'ios'|'pc'; participants: string[]; messages: Msg[] };
```

> ⚠️ **원래 PRD의 "2명" 가정 수정:** 실측 업로드는 **4~5인 단톡방**(정래현·한채린·김주형·김건우·유기훈). **N명**을 처리해야 함. 파싱 후 **'나(me)' 지정 드롭다운**(N명 중 택1) 한 번. 제품은 참가자 수에 따라 두 모드로 분기:
>
> - **참가자 == 2 → 1:1 모드 (회고형):** "헤어진 이유 / 위험 구간 / 내 실수 / 그때 이렇게 말했더라면". §5~§7. 전 애인 분석은 1:1 DM export.
> - **참가자 > 2 → 그룹 모드 (예측형):** 각 사람의 말투를 학습해 **"내가 이걸 올리면 누가 어떤 순서로 어떻게 받아칠까"** 시뮬레이션. → **§5B.**

## 5. 로컬 통계 엔진 (LLM 0회, 핵심 가치)

거대 파일을 무료 레이트리밋 안에서 처리하는 비결: **LLM 보내기 전에 통계로 '볼 구간'을 좁힌다.** 동시에 정량 근거를 확보해 "헤어진 이유"에 증거를 붙인다.

### 5.1 파생 피처 (전부 로컬 계산)

- **답장 지연(reply latency):** 발신자가 바뀌는 지점에서, 상대 마지막 메시지 → 내 첫 응답까지 시간. 사람별 평균 + **시간 흐름에 따른 추이**(지연 증가 = 멀어지는 신호).
- **대화 밀도:** 일/주 단위 메시지 수. **밀도 급락 구간 = 관계 식는 변곡점 후보.**
- **더블텍스팅:** 같은 사람이 연속 N개 보낸 구간(응답 없이 매달림 신호).
- **대화 주도권:** 일정 시간(gap > X) 후 첫 메시지를 누가 먼저 보내나(누가 먼저 연락하나).
- **질문 무시율:** `?`로 끝난 메시지 중 응답 없이 넘어간 비율.
- **메시지 길이 비대칭:** 한쪽은 길게, 한쪽은 단답("ㅇㅇ", "응") 패턴.

> ⚠️ 카톡 export에는 **읽음(1) 표시가 없다.** "읽씹"은 직접 못 구함 → 답장 지연/무응답 gap으로 **프록시**할 것. PRD/UI에서 과장 금지.

### 5.2 대화 세션 분할 (= LLM 청크 단위)

gap > **임계값(기본 3시간, 조정 가능)** 인 지점에서 대화를 **세션**으로 쪼갬. 각 세션이 자연스러운 분석 단위 + LLM 청크가 된다.

### 5.3 구간 점수화 → 우선순위

각 세션에 **로컬 위험 점수** 부여(지연 급증 + 더블텍스팅 + 밀도 하락 + 질문 무시 가중합). 점수 높은 순으로 LLM에 보낼 우선순위 결정 → **레이트리밋 절약**(전체 다 안 보내고 상위 N개만).

## 5B. 그룹 모드 — 단톡방 시뮬레이터 (예측형, the 2nd money shot)

> **컨셉:** 참가자 각자의 말투·반응 패턴을 학습해 페르소나로 만든 뒤, **"내가 이 메시지를 올리면 → 누가 / 어떤 순서로 / 어떤 말로 대화를 이어갈지"** 를 실제 카톡 스레드로 시뮬레이션. 5년치 단톡방이 페르소나 학습 데이터로 완벽함. 실존 멤버가 객석에 있으면 데모 파괴력 폭발.

### 5B.1 페르소나 추출 (1인당 LLM 1회 → 4~5콜로 끝)

사람별로 **통계 시그널(무료) + LLM 요약**을 합쳐 페르소나 카드 생성:

- **통계(로컬):** 평균 메시지 길이, `ㅋ`/이모지/물음표 빈도, 평균 답장 지연, 자주 답하는 상대, 대화 개시율, 활동 시간대.
- **LLM 요약:** 그 사람 메시지를 **층화 샘플링**(최근+과거 골고루, 너무 길면 최근 비중↑)해서 투입 → 말투/어휘/자주 쓰는 표현/리액션 스타일/잘 무는 주제 vs 씹는 주제 추출.

```json
// PersonaCard (참가자별, IndexedDB 캐시)
{
  "name": "정래현",
  "voice": "말투/문체 한 줄 요약",
  "signature_phrases": ["자주 쓰는 표현"],
  "reaction_style": "드립 받아치기 | 진지 분석 | 읽씹 | 한줄 단답 ...",
  "engages_with": ["무는 주제"], "ignores": ["씹는 주제"],
  "stats": { "avg_len": 0, "laugh_rate": 0, "median_reply_sec": 0, "active_hours": [21,22,23] },
  "talks_most_to": "한채린"
}
```

> 토큰 절약: 페르소나는 **1회 추출 후 캐시**. 시뮬레이션 때마다 재학습 안 함. 38만 줄 전체를 LLM에 안 넣고, 사람별 샘플(수백 메시지)만.

### 5B.2 시뮬레이션 엔진 (LLM 1회 / 시뮬)

입력: ① 내가 올릴 가상 메시지 ② 전원 페르소나 카드 ③ 직전 대화 맥락 몇 줄(스타일 앵커, few-shot) → 출력: **인물별 in-character 카톡 스레드**(순서·내용·딜레이 포함). 무반응(메시지 묻힘)·삼천포·우르르 몰리기 같은 단톡방 역학도 표현.

```json
// GroupSimResult
{
  "trigger": "내가 올린 메시지",
  "thread": [
    { "speaker": "김주형", "text": "...", "delay_hint": "즉답 | 5분 후 | 1시간 뒤", "in_character_note": "왜 이렇게 반응" }
  ],
  "outcome": "떡밥 물림 | 조용히 묻힘 | 싸움 남 | 삼천포",
  "who_stayed_silent": ["유기훈"]
}
```

### 5B.3 노브 (분기형 재미)

- **메시지 톤:** 도발 / 진지 / 드립 / 정보공유 / TMI → 각기 다른 캐스케이드
- **모드:** `realistic`(실제 성향대로) / `chaos`(다 터지는 버전) / `wholesome`(다정 버전)
- **시간대:** 통계 active_hours 반영(새벽엔 거의 무반응, 저녁엔 폭발)

### 5B.4 프롬프트 톤 가이드

실명 인물을 캐릭터화하므로 **친근한 과장 개그 선**에서. 특정인 비하·모욕·민감 폭로로 가지 말 것. 객석에 본인이 있을 때 웃고 넘어갈 수준으로. (실명 딥페이크·인신공격 금지 — §11.)

### 5B.5 데모 흐름

단톡방 업로드 → 멤버별 페르소나 카드가 뜸 → 입력창에 "야 우리 주말에 한라산 ㄱ?" 입력 → **각자 말투 그대로** 카톡 스레드가 좌르륵 → 톤/모드 바꿔 재시뮬 → 객석 빵터짐.

## 6. LLM 파이프라인 (map-reduce)

```text
1) 세션 분할(§5.2) → 세션[]
2) 각 세션을 토큰 예산(~2,500 토큰/청크) 기준으로 batch
3) [MAP]   각 청크 → LLM 구간분석 호출 → 세션분석 JSON
4) [REDUCE] 세션분석 JSON 전부(작음) → LLM 1회 → 전체 종합 JSON
5) [COUNTERFACTUAL] 사용자가 마커 클릭 시 → 해당 구간 + 주변 맥락만 → LLM 1회
```

### 토큰/레이트 관리 (OpenRouter 무료 기준)

- 무료 라우터 한도: 대략 **분당 20회 / 하루 200회**. 무료 모델은 **예고 없이 사라질 수 있음** → 특정 모델 박지 말고 `openrouter/free` 라우터 사용(가용 무료 모델 자동 선택).
- 6개월 대화 = 약 30청크 → MAP 30 + REDUCE 1 + 반사실 몇 회 = **1회 풀분석 ~35콜**. 데모 1명은 여유롭지만 **여러 명 라이브 시 200/day 초과 위험**.
- **데모 모드:** 상위 위험 세션 **8개만** MAP(§5.3) → 8콜로 압축. 또는 발표용 1건 미리 분석해 IndexedDB에 캐시.
- MAP 호출은 **병렬 자제**(분당 20회 한도) — 동시성 3~4로 제한 + 429 시 지수 백오프.
- 무료 모델이 JSON 모드를 항상 보장 안 함 → **"JSON만, 마크다운/백틱 금지" 프롬프트 + 방어적 파싱**(```json 펜스 제거 후 try/catch).

## 7. 프롬프트 & 출력 스키마

> 공통 톤 가이드(프롬프트에 삽입): **통찰과 성장 관점으로. 일방적 자기비난을 증폭하지 말 것.** 패턴을 짚되 "이래서 넌 차였다"식 단정 금지. 근거(실제 대사 인용)를 반드시 붙일 것. — 이게 윤리적 기본값이자, 공유하고 싶어지는 결과물을 만드는 디자인 포인트.

### 7.1 MAP — 구간 분석

```text
system: 너는 두 사람의 카톡 대화 한 구간을 분석한다. '나'는 {me}.
        아래 JSON 스키마로만 응답. 마크다운/백틱/설명 금지.
user:   [구간 메시지들 + 각 메시지의 답장지연(초) 메타]
```

```json
{
  "segment_id": "string",
  "time_range": "YYYY-MM-DD ~ YYYY-MM-DD",
  "summary": "한 줄 요약",
  "tension_score": 0,
  "who_is_pulling_away": "me | them | neither",
  "risky_moments": [
    { "quote": "실제 대사 인용", "why": "왜 위험했나", "severity": 0 }
  ],
  "my_mistakes": [
    { "quote": "내가 한 말", "issue": "무엇이 문제였나", "better_version": "이렇게 말했으면" }
  ],
  "tone": { "me": "감정 톤", "them": "감정 톤" }
}
```

### 7.2 REDUCE — 전체 종합

```text
user: [모든 세션분석 JSON 배열 + 통계 요약(답장지연 추이, 밀도 하락 등)]
```

```json
{
  "relationship_arc": "전체 흐름 서사 3~4문장",
  "breakup_reasons": [
    { "reason": "원인", "evidence": ["근거 대사1", "근거 대사2"] }
  ],
  "turning_points": [ { "when": "시점", "what": "무슨 일" } ],
  "your_patterns": ["반복된 내 패턴"],
  "their_patterns": ["반복된 상대 패턴"]
}
```

### 7.3 COUNTERFACTUAL — "만약 이때…"

```text
user: [선택된 구간 + 직전 맥락] + "이 시점의 {me} 대사를 다르게 했다면 어떻게 흘러갔을지 시뮬레이션"
```

```json
{
  "original_line": "원래 내가 한 말",
  "suggested_line": "이렇게 말했으면",
  "rationale": "왜 더 나은가",
  "simulated_timeline": [
    { "sender": "string", "text": "string", "delay_hint": "즉답 | 1시간 후 | 다음날" }
  ],
  "outcome_delta": "결과가 어떻게 달라지는가 한 줄"
}
```

> 재미 옵션: `mode: "realistic" | "best_case" | "disaster"` 파라미터로 "현실적 / 해피엔딩 / 더 망함" 세 갈래 생성 → 분기형 데모로 확장(앞선 멀티버스 카톡 컨셉과 합류).

## 11. 리스크 & 주의

- **포맷 변형(최대 함정, 실측 확인):** 맥OS=CSV, 모바일/PC=txt로 완전히 다름. **안드로이드는 폰 언어에 따라 한글/영문 포맷이 또 갈림**(실측 파일은 영문). CSV는 papaparse로 쉬움. txt는 ① BOM ② CRLF→LF ③ **U+202F→공백** 전처리 안 하면 매치율 0% — 이 셋이 진짜 지뢰. 첨부 `공돌이들.csv` + `KakaoTalkChats.txt` 둘 다 골든 샘플로.
- **파일 규모:** 실측 안드 export가 **23MB·38만 줄·5.7년치**. 통컨텍스트 절대 불가 → 통계 선분석(§5) + 청킹(§6) + 페르소나 샘플링(§5B.1)은 선택이 아니라 필수. 파싱·통계는 전부 클라이언트(웹워커 권장), LLM엔 좁힌 청크/샘플만.
- **읽음 표시 없음:** export엔 1(읽씹) 없음. 지연/gap으로 프록시하되 UI에서 단정 금지.
- **무료 레이트리밋:** 200/day. 라이브에서 여러 명 쓰면 터짐 → 데모 모드(상위 N구간/페르소나 캐시) + 발표용 캐시 + 백업으로 유료 키 1개 환경변수 대기.
- **무료 모델 휘발성:** 특정 모델 하드코딩 금지, `openrouter/free` 라우터로.
- **감정·실명 무게:** 1:1은 진짜 이별 대화 → 통찰·성장 프레임, 자기비난 증폭 금지. 그룹은 실명 인물 캐릭터화 → 친근한 과장 개그 선까지, 비하·인신공격·실명 딥페이크 금지(§5B.4).
- **프라이버시 신뢰:** "서버 저장 안 함"은 실제로 지켜야 함(원문은 LLM 호출 시 청크/샘플만 transient 전송). 이게 곧 차별점.

## 12. LLM 호출·토큰 예산 (2026-06-27 실측 코드 기준)

현재 구현(`web/src/lib/llm/config.ts`, `client.ts`) 기준. OpenRouter 무료 tier는 **토큰보다 일 200회·분 20회**가 먼저 병목.

### 호출 수 (API calls)

| 플로우 | 호출 | 비고 |
|--------|------|------|
| 1:1 풀분석 | **9** | MAP 8 (`maxSegments` 기본) + REDUCE 1 |
| 반사실 1탭 | **1** | realistic / best_case / disaster 각 1 |
| 그룹 페르소나 | **N** | 참가자 수 (공돌이들=5) |
| 그룹 시뮬 1회 | **1** | trigger마다 |

### 추정 토큰 (in+out, 대략)

| 시나리오 | 총 tok |
|----------|--------|
| 1:1 풀분석 1회 | ~4만~5.5만 |
| + 반사실 3탭 | +~1.2만~1.8만 |
| 그룹 (5 페르소나 + 시뮬 2) | ~2.5만~3.5만 |
| 발표 리허설 1세트 (1:1+반사실1+그룹) | ~7만~9만 |

입력 상한: MAP ~6,000자/청크(≈2,500 tok). 출력 상한: MAP 1,200 · REDUCE 1,600 · 반사실 1,300 · 페르소나 900 · 그룹 시뮬 1,800.

### 데모 운영 가이드

- **혼자/리허설 10회+**: 200/day 여유.
- **당일 라이브 ~10명**: 1인 ~18콜 → ~180콜, 빠듯. **사전 IndexedDB 캐시 1건** 필수.
- **15명+**: 200/day 초과 위험 → 발표는 캐시만 보여주거나 `maxSegments` 5로 축소(6콜/1:1).
- **품질**: 로컬 통계=매우 안정. LLM=위험 top-8만 분석→핵심 장면은 좋음, 긴 세션 중간 생략. 무료 모델 흔들림→방어적 JSON 파싱.
